## 0. 一句话

把《单词风云录》的**战斗循环**摘出来，砍掉全部剧情，做成《Elaine学英语》里的「闯关」：花 100 ⭐ 进一次，按难度档一路往上打，拼对的词**当场喂给记忆曲线**。打得越深赚得越多，但只有"该复习的词"才给星。进度全写进 `profiles/<名字>.json`，打 BOSS 回血，中途能进商店买丹药。

## 3. 一局的结构

```
进入 → 扣 100 ⭐ → 第 1 档
第 n 档：抽 10 个 T(n) 词当小怪，一只一只上 → 本档 BOSS → 第 n+1 档
第 8 档打完 → 二周目：词池回 T1，词价减半，怪更硬
```

| 项 | 值 | 说明 |
|---|---|---|
| 每档小怪 | 10 只 | 每只一个词，拼对即散 |
| 每档 BOSS | 1 只 | 3 个词，血厚，会反击；**倒下即回血**，见 §3.1 |
| 单档时长 | 3–4 分钟 | 手机上一局 8 档约 30 分钟，中途可退 |
| 局内商店 | 随时可开 | 战斗中开商店买丹药，回来原地继续，见 §3.2 |
| 死亡 | 结算 70%，不退门票 | 星照给，灵石按 70% |
| 主动退出 | 立即结算，同上 | 不做"中途存档"，但**按已打档数补结算**，见 §3.3 |

> **为什么不是"一关一关"**：无尽模式没有"关"的概念，只有"档"。档是词汇难度，不是地图。**地图每档换一张**（见 §7.3），一轮五档，第六档回到第一张并给妖王加「狂暴·」前缀。

### 3.1 打死 BOSS 回血

| 项 | 值 |
|---|---|
| 回复量 | `round(maxHp × 0.25)`，不超过 `maxHp` |
| 二周目起 | 降到 `0.15` |
| 触发时机 | BOSS 散掉的**那一帧**，不等结算屏 |
| 表现 | 气血条上涨 + 一格绿光 + 一声钟鸣，2 秒内不能再次触发 |

一局 8 档、半小时，中途没有恢复点的话，第 3 档以后基本是"剩多少血打多少"，越打越缩。BOSS 是天然的分段点，在这里给一口血，**让"打得稳"有回报，同时不动"拼错就掉血"的压力**。

数值校验：初始 `maxHp = 100`，普通怪撞一下 −4（`game.js:1157`），回 25 等于抵六下。够喘一口气，不够白送。穿上太虚战袍（`maxHp = 400`）时回 100，同理。

### 3.1b 过关继承哪些资源

换档（`arcadeGoTier`）时**不清零**的东西：

| 资源 | 是否继承 | 说明 |
|---|---|---|
| 气血 | ✅ 按剩余值带过去 | 否则 BOSS 回血毫无意义 |
| **气劲** | ✅ `min(100, 剩余值)` | 攒到 80 放的大招，不该在换档那一秒蒸发 |
| 灵石 | ✅ | 局内货币，整局有效 |
| 装备 / 技能 / 功法 | ✅（仅限本局） | 走 `applyMeta` 重新折算；**下一局不带，回新手村重来** |
| 连击 / 冷却 / 当前词 | ❌ | 战斗现场重置 |

新开一局（`ARCADE.start`）时气劲从 0 起、刀甲功法全清 —— **继承只跨档，不跨局**。理由：每局都该有从新手村一路刷上去的完整过程，否则开局就是满配，前几档等于空过。

### 3.1c 一只怪要拼几个词（同一个词不重复）

**规则：拼对但怪没死 → 立刻换一个新词。** 同一只怪身上，同一个词只拼一次。刀数等于「这一只要拼几个不同的词」。

原来的实现只在 `e.segs > 1`（血条分段，第 6 档起）时才换词，所以第 1–5 档的小怪会逼着玩家把同一个词拼 2–4 遍，看着像「拼对了却不认」。现在无尽模式下所有怪都换，BOSS 也换。

配套的数值（`arcMobHp` / `bossHp`）：

| | 原来 | 现在 | 第 8 档结果 |
|---|---|---|---|
| 小怪血量增速 | `22 × 1.32^(n-1)` | `22 × 1.18^(n-1)` | 154 → 70 血，4 刀 |
| BOSS 倍率 | 小怪 × 3.2 | 小怪 × 2.4 | 493 → 168 血，8 刀 |
| 每档词池 | 22 个 | 50 个 | 一档 10 怪 + BOSS 每刀换词，够用 |

一档的总词数没变（刀数本来就那么多），变的是「每个词只出现一次」。第 1 档仍是 2 刀一只怪。

**判定的归属也收紧了**：超时和拼错都用 `inputOwner()`（前缀真能对上的那只）而不是 `focusEnemy()`（会回落到最近的怪）。三只怪同屏时，正在拼的那只被剑气劈死、或词被换掉，输入框里残留的前缀不再算到旁边那只头上；这种情况直接清空输入，不记任何词错。

### 3.2 局内商店：回血道具

**先说结论：这条路在代码里本来就是通的，只是数据被清空了。**

`meta.js` 的 `SHOP.item` 是个空数组，上面留着注释「丹药撤掉了：回血回气不如换一把好剑，格子全让给武器防具」。但 `game.js` 的购买分支一直没删（`campBuy()`，1604–1626 行）：

```js
} else if (row.kind === 'item') {
  if (row.item.heal) p.hp = Math.min(p.maxHp, p.hp + row.item.heal);
  if (row.item.qi)   p.qi  = Math.min(100, p.qi + row.item.qi);
  campSay('服下「' + row.item.name + '」');
}
```

`campRows()`（1570–1578 行）也照样会遍历 `SHOP.item`。**所以只要把数组填回去，商店里就有丹药卖了，渲染和购买一行都不用改。**

要填的数据（价跟八剑八甲同一条价格带，参考 40 → 810）：

| 道具 | 效果 | 价 | 定位 |
|---|---|---|---|
| 小还丹 | 气血 +25% | 30 | 每档都买得起一颗 |
| 大还丹 | 气血 +60% | 90 | 约等于一件低阶甲，救命用 |
| 回气散 | 气劲 +50 | 45 | 差一格放大招时顶上 |

**一处小改**：现在 `heal` 只吃固定值，`maxHp = 100` 时 +25 有意义，`maxHp = 400` 时等于没有。所以让 `heal` 允许写成百分比字符串：

```js
// campBuy 里那一行改成
var add = typeof row.item.heal === 'string'
  ? Math.round(p.maxHp * parseFloat(row.item.heal) / 100)
  : (row.item.heal || 0);
p.hp = Math.min(p.maxHp, p.hp + add);
```

**战斗中怎么开**

现在商店只在关卡之间（`S.scene === 'camp'`）。要能在战斗里打开，**不碰战斗逻辑，只加一个开合开关**：

```js
function openShopInRun(){
  if (S.scene !== 'play') return;
  /* 字段跟 enterCamp() 对齐，少一个渲染就会 undefined */
  S.camp = {
    tab: 0, sel: 0, page: 0, hover: -1, hoverTab: -1,
    hoverGo: false, hoverPrev: false, hoverNext: false,
    msgT: 3, msg: '灵石 ' + S.player.stones,
    fromRun: true            // 唯一的开关，其它全沿用
  };
  S.scene = 'camp';
}
function backToRun(){
  if (S.camp && S.camp.fromRun) { S.scene = 'play'; }
}
```

因为 `S` 是整局状态，切 `scene` **不销毁 `S.enemies`、不重置气血、不重置冷却和当前词**。切回来就是原地继续，不需要序列化任何东西——这是这套代码天然的好处，别去改成"退出战斗再重开"。

只有三处要接：
1. 战斗界面加一个"钱袋"按钮（右上角，跟大小写开关并排），点它 → `openShopInRun()`
2. `campNextLevel()`（1643 行）在 `fromRun` 时改调 `backToRun()`，别跳下一关
3. 商店底部那颗"下一关"按钮，`fromRun` 时文案改成「回战场」

约 40 行。

**一条经济约束**：灵石是**局内货币，局末清零**（§4.1），所以不存在"攒三局钱一次花"。丹药是**买了立刻吃**——现有 `campBuy()` 的 `item` 分支就是这样，直接 `p.hp += heal`，不进背包，所以也屯不起来。

但**买到的剑、甲、技能只在这一局有效，下一局从空手起**。这一条也很重要：装备是"这趟刷出来的本钱"，钱是消耗品，两者都不跨局。每局都从新手村一路打上去，前两档才有意义；不然一旦某局攒出满配，之后每局开局就跳过新手村，练词节奏也跟着失衡。

### 3.3 被打断怎么办

无尽模式不存局中进度，但**门票不能白吃**。所以每档结束往档案里落一个待结算点：

```js
arcade.runPending = { tier: 3, stars: 41, stones: 260, ts: 1762500000000 }
```

下次进应用时，如果 `runPending` 还在（说明上一局是刷新/掉线/关页面结束的），按它补一次结算再清空。这样孩子刷新一下最多丢当前档，不会丢整局。

这条是 §5.6 那个写入口的直接后果——只要每档落一次盘，这个机制几乎是免费的。

### 3.4 提示：20 灵石买一个答案，先停住再确认

打不出来的词不该让孩子干耗着，但也不能一键过关。做成「买答案 + 确认」两步：

| 步骤 | 发生什么 |
|---|---|
| 点右上角灯泡 | 扣 **20 灵石**（不够就点不动），把当前词的完整拼写填进输入框 |
| 填完立刻 | **整个世界停住**：`S.paused = true`，`update()` 直接 return，连 `S.t` 都不推进 |
| 弹面板 | 显示单词 + 释义 + 两个按钮：**确认出招 / 自己拼** |
| 确认 | 解除暂停，主角冲上去一刀。**小怪直接清掉，妖王只削 34% 血** |
| 自己拼 | 输入框退回提示前的样子（拼了一半还是那一半），灵石不退 |

几个刻意的取舍：

- **暂停期间不计时**。`S.t` 不走，键入时限、怪物推进、弹丸飞行、气劲冷却全部冻结——买提示不是买罪受。
- **提示那一刀不算「自己拼对」**。`markWord(w,'h')` 单独记一档，主应用侧 `srsPeek()` 只把到期时间推到 10 分钟后，不升档、不给星。想靠灵石刷星是刷不动的（§4.3）。
- **不涨连击、不给气劲**，伤害固定 ×0.7 —— 提示是保底，不是主要打法。
- **两次之间冷却 6 秒**（`HINT_CD`），暂停期间冷却也不减，防止连点把钱烧穿。
- 灵石 8 / BOSS 60 的产出下，一档 10 小怪 + 1 BOSS 收入约 140，**最多提示 7 次**——资源换时间，不换分数。

### 3.5 键入时限：从敲第一个字母开始算

原来没有硬性时限，只要不被弹丸打死就能慢慢磨。现在给每个词一个窗口：

```
时限 = (32 + 词长 × 2.4) × 倍率        // fast: 41.6s   magazine: 56s
```

> 小朋友手慢，最初是 `(16 + 1.2/字母)`，2026-11 整体放宽一倍。配合提示的 ×2，四字母词最宽能到 83 秒。

- **只在真的在拼的时候走表**（`S.input` 非空）。读题、想中文、发呆都不罚。
- 超时按拼错处理：断连击、气劲 -10、气血 -4、这个词换一个新的（`rerollWord`），并且记一次 SRS 错误。
- 输入框下方有一条 2px 的细进度条，绿 → 黄 → 红。
- **用过一次提示，`timeBuff` 变 2，这一局所有词的时限都翻倍**（跨档保留，`startArcade` 才清零），左上角挂一个「时限 ×2」的标记。再点提示不会叠成 4 倍。
- **点提示会念一遍**：先逐字母（`A. P. P. L. E.`）再念整词（`apple`），走主应用那套 `SM.voice.sayEn`（Edge TTS → 服务端 → 浏览器语音三级兜底），短语（`a pair of`）只念整句、不逐字母。游戏侧只管喊一声 `ARCADE.onSpell(word)`，怎么念、用什么嗓音全由宿主决定，引擎里没有一行 TTS 代码。

### 3.6 新手教程：两页图文说明，随时可跳过

第一次进闯关（存档里 `arcade.tutSeen` 还是空）在开局 520ms 后自动弹出，之后想看可以从入口卡片再开。两页：

| 页 | 讲什么 | 背景 |
|---|---|---|
| 1 | 音效 / 语音开关、大小写、局内商店、提示（20 灵石）、闪避 + 三招、字母盘 / 切换 / 跳过 / 退格 | 战场 |
| 2 | 两个页签、商品卡（点了就买）、翻页箭头、回战场 | 洞府天地（局内商店） |

实现是「游戏出坐标，教程画框」两段式，两边只靠一个数组耦合：

- 游戏侧只多一个 `ARCADE.hotspots(page)`，返回 `{id,x,y,w,h,tip,place,num}`，坐标一律是 canvas 逻辑坐标（480×270）。
- `arcade/tutorial.js` 用 `canvas.getBoundingClientRect().width / 480` 换算成屏幕像素，铺一层 `rgba(4,10,12,0.58)` 遮罩，每个框画 2px 金边 + 淡黄底。
- **说明文字怎么放**：宽度 ≥ 560 且是战斗页时贴边写（`place` 指方向，靠边会翻面）；商店页和手机窄屏一律改成「框上打编号 + 底部说明卡」——480 宽的画布上贴边写字必然互相压住。右上角**音效和语音只隔 2px**，合成一块热区、共用一条说明（「音效开关 · 语音朗读开关」），各写一条会在右边互相压住。
- **编号挂哪儿**由 `num` 指定：`tl` 左上角（默认）、`tc` 上边正中（页签上面有空间）、`r` 右边外侧（商店底下翻页 / 回战场那几个框排得紧，只能往右让），最后统一夹回可视区，免得贴屏幕边被切掉。
- 第二页把底部 DOM 键盘 `visibility: hidden`（**只改 visibility，不改 display** —— 改 display 会重算画布尺寸，所有框都得重新量），说明卡跟着贴到画布下沿。
- 暂停直接复用游戏的 `S.paused`；跳过和看完都走 `close()`，恢复键盘与暂停。
- 首帧拿到的可能是布局变化前的画布矩形（进商店、字体加载都会改尺寸），所以 `render()` 之后还会在 rAF×2 和 360ms 各重画一次。
- 竖屏时字母盘在画布外（DOM 键盘），战斗页要单独补一条框，用 `.arc-keys` 的屏幕矩形。

**代价**：`tutorial.js` 不接管任何游戏事件，也不认识 `S`，只认 `state() / hotspots(page) / canvas() / openShop() / closeShop()` 五个接口，所以独立调试页 `arcade/index.html?tut=1|2` 能直接复用同一份。

### 3.7 台词：招式喊名 + 十一类战斗台词（TTS）

台词**全在 `arcade/src/lines.js`** 一处，引擎只负责说「发生了什么」。改文案不用碰游戏逻辑，也不用碰宿主。

| 类 | 什么时候说 | 条数 | 必带 |
|---|---|---|---|
| `weapon` | 买了剑 | 8 | 剑名 + 「装备了」+ 攻击值（部分条） |
| `armor` | 买了甲 | 8 | 甲名 + 「装备了」+ 气血值（部分条） |
| `skill` | 剑意 / 罡气 / 身法 / 会心 加点 | 8 | 技能名 + 等级 |
| `art` | 破空斩 / 寒冰咒 / 雷罡印 升级 | 8 | 招式名 + 等级 |
| `attr` | 同上，另一种说法 | 8 | 技能名 + 「XX 属性又升级了」 |
| `hit` | 出手：**只**在暴击 / 连击 / 击杀，且三成机会 | 14 | —（哈！喝！呀！） |
| `hurt` | 挨打 | 12 | —（好痛好痛！） |
| `dodge` | 闪避 | 13 | —（闪身步 / 我闪！） |
| `dead` | 血空了 | 10 | —（我还会回来的！） |
| `heal` | 小还丹 / 大还丹 | 8 | 丹药名 或「好险好险」 |
| `qi` | 回气散 | 8 | 道具名 或「回蓝了」 |

规则：

- **技能升级随机二选一**：一半说「剑意升级了！现在 2 级」，一半说「剑意升级了，攻击属性又升级了！」。属性由 `ATTR_OF` 映射：剑意→攻击、罡气→气劲、身法→闪避、会心→暴击。**「属性又升级了」只跟技能走，不跟装备**（装备只说攻击 / 气血数值）。
- **出手台词绝不每刀都响**：普通一刀一声不吭 —— 那会盖住单词发音，孩子听不清。只在暴击、连击（combo ≥ 2）、击杀时掷 30% 的骰子；`src === 'art'`（招式命中）已经有喊名，也不再叠一句。
- **挨打四秒限一次**，而且致死那一击只说「倒下」不说「好痛」—— 两句挤在一起会被节流吞掉。
- 台词库自己记「上次挑的是哪条」，同一类不连说两遍。

宿主侧（`js/arcade.js`）三道闸：

1. 1.2 秒内同一句不重复；
2. 两句之间至少 650ms（挨打、闪避、出手可能同一瞬间撞上）；
3. **正在拼读单词时一律闭嘴** —— 那是孩子在听字母，不能被一句「哈！」盖掉。

朗读失败、宿主没接 TTS、台词库没加载，都只是没声音，不影响这一局。

#### 多音字：送 TTS 前换同音字，屏幕上不动

`lines.js` 里有一张 `PRON` 表，`pron(text)` 在**送进 TTS 之前**把多音字换成同音字，屏幕上的字一个不改：

| 原文 | 送 TTS | 为什么 |
|---|---|---|
| 小还丹 | 小环丹 | 「还」多数中文音色念 hái（还有），武侠里该念 huán（还原） |
| 大还丹 | 大环丹 | 同上 |

- 「血回来了」「我还会回来的」这类里的「还」本来就是 hái，不在表里，不替换。
- 引擎与屏幕完全不知道这件事：`campSay`、商店卡片、结算里显示的还是「小还丹」。
- `js/arcade.js` 的 `sayName()` 里调用 `ARCADE_LINES.pron()`；表里没有 `ARCADE_LINES`（比如调试页没加载台词库）就原样念。
- 要纠正别的字，往 `PRON` 里加一行即可，测试会自动覆盖。

### 3.8 语音开关：跟音效分开管，按钮就在喇叭下面

画布右上角那一列按钮，从上到下：**音效 → 语音 → 点读 → 大小写 → 买药 → 提示**。

| 按钮 | 位置 | 图标 | 管什么 |
|---|---|---|---|
| 音效 | `BTN` y=4 | 喇叭 | Web Audio 合成的打击 / 叮咚声 |
| 语音 | `BTNV` y=28 | 对话气泡 | 所有 TTS：招式喊名、战斗台词、点提示的逐字母拼读 |
| 点读 | `BTN2` y=52 | ABC | 底部字母盘能不能点 |
| 大小写 | `CASE_BTN` y=76 | Aa | 输入时是大写还是小写 |
| 买药 | `SHOP_BTN` y=100 | 钱袋 | 局内商店 |
| 提示 | `HINT_BTN` y=124 | 灯泡 | 20 灵石买一个答案 |

- 关掉语音后 `js/arcade.js` 的 `sayName()` 和 `speakSpell()` 各自**第一行就 return**，一句都不念；正在念的那句用 `SM.voice.stop()` 立刻掐掉，拼读的下一段也不会再来。
- 状态存本机 `localStorage['sm_arc_voice']`（`'0'` 关 / `'1'` 开）—— 这是「这台设备的喇叭要不要响」，不跟着账号上云。开局宿主调 `ARCADE.setVoiceOff(voiceOff)` **静默**同步，按钮一进来就是关的样子。
- 引擎只负责画按钮 + 回调 `ARCADE.onVoice(off)`，不碰任何语音实现 —— 跟 `onSay` / `onSpell` 一个路子。
- 教程第 1 页把**音效和语音合成一块热区**、一条说明「音效开关 · 语音朗读开关」：这两颗只隔 2px，各写一条会在右边互相压住。

> 顺带修了 `.tut-tip` 的一个老毛病：贴右边的说明（`place:'left'`）可用宽度是负数，只有 `max-width` 时会被压成「一字一行」，现在加了 `width: max-content` 先撑开再兜上限。

### 3.9 直达入口：/play 与 /play-ipad（练习局，不扣星）

给「打开就能玩」用，跳过首页卡片和入场确认。两个地址分别对应手机和 iPad 布局：

| 用途 | 地址 | 实际加载 |
|---|---|---|
| 手机 | `/play`（或 `/play.html`） | `index.html?play=1&phone=1` |
| iPad | `/play-ipad`（或 `/play-ipad.html`） | `index.html?play=1&ipad=1` |

**默认是练习局**：不扣 100⭐、不加星、不写记忆曲线、不更新 `bestTier` / `runs` / `daily`，整局零落盘 —— 拿来做测试、给小朋友随便打两把都不会污染档案。要按正常规则扣星，就在地址后面加 `&free=0`。

参数表：

| 参数 | 作用 |
|---|---|
| `play=1` | 打开即进闯关，首页先藏着（`html.play-boot`） |
| `phone=1` | 强制手机布局（在 iPad 上调试手机版用） |
| `ipad=1` | 强制平板布局，不再等自动识别 |
| `free=0` | 关掉练习局，走正常门票与返星 |
| `who=Elaine2` | 换一份档案；不写就用这台设备上次用的，再没有就默认 `Elaine` |

实现分四层，互相不越界：

1. **静态入口**（`play.html` / `play-ipad.html`，以及目录形式 `play/index.html` / `play-ipad/index.html`）：只做 `location.replace()`，把 `?who=` / `?free=` 原样带过去。用目录形式是为了 `/play` 这种没有扩展名的地址在**纯静态服务器**上也能用（`SimpleHTTPRequestHandler` 会 301 到 `/play/`），不必重启服务端。
2. **`index.html` 头部**：`param()` 收参数 → 必要时写 `localStorage['sm_profile']` → 存进 `window.__SM_PLAY` → 挂 `play-boot` 类；`#bootVail` 是「正在进入单词闯关…」的遮罩，真开始画第一帧时由 `startRun()` 撤掉。
3. **`js/app.js` 末尾**：`if (window.__SM_PLAY) SM.arcade.quickStart({free})` —— 首页照常 render，只是被 CSS 藏着，所以退出游戏后什么都不用重建。
4. **`js/arcade.js`**：新增 `quickStart(opts)`（不弹入场确认）与 `startRun(free)` 的 `free` 分支；`finishRun` 在练习局把星数归零、跳过 `saveStars/dailyAdd/bestTier`；结算页显示「练习模式 · 不计分 · 不扣星 · 不写记录」，主按钮变「再来一局」、另给一颗「回首页」。`boot()` 在 `__SM_PLAY` 下**不跑** `recoverPending()`，免得测试顺手把上次没结算的星补进档案。

> 平板竖着拿时不锁方向，只在开局 1.5 秒后 toast 一句「横过来玩，字母盘更好按～」。
> 加载超过 9 秒会撤掉遮罩回首页，不会把人永久卡在「正在进入」。

## 4. 积分

### 4.1 双货币

| 货币 | 来源 | 用途 | 能否互换 |
|---|---|---|---|
| ⭐ 星 `sm_stars` | 学习答题、闯关结算 | 入场券、成就 | 否 |
| 灵石 `arcade.stones` | 只在闯关内掉落 | 买剑、买甲、学招、买丹药；**灵石局末清零，买到的剑甲技能也只在本局有效** | 否 |

理由：星是学习激励，一旦能靠"玩"无限产出，学习就没动力了。灵石专用于局内成长，形成"打得深 → 装备好 → 打得更深"的正循环。

### 4.2 星价表

词价 = `ceil(档 / 2)`，BOSS = `10 + 档 × 2`

| 档 | 词池 | 单词价 | BOSS | 本档满收 | 累计 |
|---|---|---|---|---|---|
| 1 | T1 | 1 | 12 | 22 | 22 |
| 2 | T2 | 1 | 12 | 22 | 44 |
| 3 | T3 | 2 | 14 | 34 | 78 |
| 4 | T4 | 2 | 14 | 34 | 112 |
| 5 | T5 | 3 | 16 | 46 | 158 |
| 6 | T6 | 3 | 16 | 46 | 204 |
| 7 | T7 | 4 | 18 | 58 | 262 |
| 8 | T8 | 4 | 18 | 58 | 320 |

入场 −100，八档全清 +320，**净赚 220**。
二周目起词价减半（向上取整），BOSS 价不变 —— 深打仍值钱，但刷不动。

### 4.3 防刷分（关键）

> **只有"该复习的词"（`due <= now`）和"没学过的新词"（`reps === 0`）给星。**
> 已掌握且未到期的词，拼对只给灵石，**不给星**。

这条一加，反复打第 1 档自动失效——系统没到期就不给钱。同时它让"闯关"变成真正的复习场。

另设每日返星上限 `DAILY_STAR_CAP = 400`（可调），防代刷。

### 4.4 结算

```
stars = 0
for w in solved:
    rec = words[w]
    if rec.reps === 0 or rec.due <= now:
        stars += ceil(tier / 2)
stars += bossesKilled * (10 + tier * 2)
if died: stars = floor(stars * 0.7)
if stars > dailyLeft: stars = dailyLeft
```

星星之外还列一份**本局词单**，按「最后一次」归类（先错后对只算背下来，不重复出现）：

| 行 | 含义 | 记法 |
|---|---|---|
| ✅ 背下来 | 自己拼对了 | `'c'` |
| 💡 看了提示 | 花灵石买了答案 | `'h'` |
| ⏭ 跳过 | 按了跳过，或者目标跑掉了 | `'s'` |
| ❌ 拼错 | 拼错且没补上（含键入超时） | `'w'` |
| ⚔ 技能清掉 | 被大招 / 技能顺手带走，等于没练 | `'k'` |

数据来自 `ARCADE.summary().words`（引擎里 `wordEv` 一张表累积），`js/arcade.js` 的 `wordReport()` 归并成五档。有跳过的词会在下面补一句「下次更容易再遇到」——这些词的到期时间被推近了。

## 5. 记忆曲线

### 5.1 为什么不复用 `memory.js`

`memory.js` 管的是**现场生成的语法题**，key 是题 id，两级就毕业。单词是另一回事：

- 词是**有限集合**，一个词要跨几十天反复见面
- 词的难度和"语法点掌握度"不是一回事
- 两套毕业标准混在一起，`待复习` 数字会失真

所以：共用档案与积分，**词池独立**。

### 5.2 数据结构

```js
// 存在档案的 sm_words 下，key 是单词小写
"classmate": {
  w: "classmate",
  ef: 2.5,          // 难度因子，暂不参与计算，留给以后
  step: 0,          // 当前在间隔表的第几档
  ivl: 10,          // 当前间隔（分钟）
  due: 1762500000000,
  reps: 0,          // 累计拼对次数
  lapses: 0,        // 累计拼错次数
  last: 1762400000000,
  src: "book"       // book | wrong | arcade
}
```

### 5.3 间隔表

```js
GAP = [10, 30, 720, 1440, 2880, 5760, 10080, 21600, 43200, 86400]  // 分钟
//    10m  30m  12h   1d    2d    4d     7d     15d    30d    60d
```

| 事件 | 规则 |
|---|---|
| 新词拼对 | `step = 1`，`due = now + GAP[1]` |
| 拼对 | `step = min(9, step + 1)` |
| 拼对且用时 ≤ 3 秒 | 额外 `+1` 档（上限 9），奖励"熟"不奖励"瞎按" |
| 拼对但用时 > 8 秒 | 不升档，只延长 `due` |
| 拼错 | `lapses++`，`step = max(1, step - 2)` |
| 拼错后 | **本局立即回炉**，同一局内换一只怪再出一次 |

> 回炉这条是关键：错了当场补，别等明天。这也是游戏相对做题的唯一优势。

### 5.4 出词配比（每档 10 只）

| 类型 | 占比 | 排序 |
|---|---|---|
| 逾期词 | 60% | `due` 越早越优先 |
| 未学过的新词 | 30% | 按 tier 从小到大 |
| 随机复习（未到期） | 10% | 随机，**不给星** |

不足时按优先级顺延，保证永远凑得满 10 个。

### 5.5 与游戏原有 `wordStat` 的关系

游戏里已有 `{c, w, s, k, st}`（拼对/拼错/跳过/技能打死/连续）。**不删**，作为上报原料：

- `c` → 拼对（带用时）
- `w` → 拼错
- `s` 跳过 / `k` 被技能打死 → **不算复习**，`reps` 不加，`due` 不顺延（防止用技能刷"已复习"）

### 5.6 存档：全部汇进主应用那份总 JSON，游戏不另存

**先看主应用已经有什么**（`js/core.js` 70–110 行）：

```js
const PDB = window.__SM_DATA;        // 就是 profiles/Elaine.json 那份 JSON 本体
S.set = function (k, v) {
  if (SERVER) { PDB[k] = v; queue(); return; }   // queue = 400ms 防抖
};
function flush() { fetch('/api/profile', { body: JSON.stringify({ name, data: PDB }) }) }
```

也就是说：**`S.set(k, v)` 写进去的东西，400ms 后会自动跟着整份 JSON 一起落到 `profiles/Elaine.json`。** 不需要新写同步、不需要新开接口、不需要 `server.py` 改动。

所以"汇入总存档"这件事，落实到代码上只有一句话：

> **游戏只调 `SM.store.set`，一个 localStorage 都不许直接碰。**

```js
// 游戏侧唯一的写法
SM.store.set('arcade', {
  bestTier: 5,                          // 历史最高档（只做展示和"上次打到哪"的提示）
  runs: 12,                             // 打过多少局
  lastRun: { tier: 5, stars: 88, ts: 1762500000000 },
  runPending: null                      // 见 §3.3，被打断时才有值
});
```

注意这里**没有** `equip` / `skills` / `arts`：剑甲、功法、技能等级是局内养成，只在 `S.meta` 内存里活一局，局结束就随内存一起丢，下一局重新从新手村刷（§3.1b）。

落盘之后，`profiles/Elaine.json` 里就多一个跟 `sm_stars`、`sm_q` 平级的 `arcade` 键。换设备、换浏览器、iPad 和手机之间，进度都在。

**必须清掉的老账**：`game.js` 里现在散着一堆裸 localStorage，服务端永远看不到：

| 现在 | 改成 | 说明 |
|---|---|---|
| `dfyl_meta` | 不存 | 灵石、装备、技能等级全是局内状态，一局一清 |
| `dfyl_best` / 关卡进度 | `arcade.bestTier` | 无尽模式只记最高档 |
| `dfyl_case` | 不存 | 字母盘大小写，纯内存即可 |
| `dfyl_skin` 等其余 `dfyl_*` | 删 | 没有对应用途 |

一条硬规矩：**`arcade` 之外不新增任何顶层键。** 全部塞进 `arcade` 一个节点，以后要清理、要导出、要做"重置闯关进度"，只动这一个键。

**写的时机**（这不是为了省流量，是为了别把整份 JSON 冲掉）：

一局要拼 100 多个词。如果每 `markWord` 就 `set` 一次，防抖会把它压成"每 400ms POST 一次整份档案"，半小时一局发几百次全量。所以：

```
拼词        → 只改内存（S.player.stones / SRS 待写队列）
每档结束    → SM.store.set('arcade', …) + 合并 sm_words + 落一次 runPending
买一次东西  → 只动内存（局内养成不落盘，下次开局本来就是空的）
死亡 / 退出 → 结算后 set，清 runPending
```

**唯一写者**：`S.set` 是同步、可重入的，不存在两边互相覆盖。唯一的真坑是"刷新丢整局"，那件事交给 `runPending` 补结算（§3.3）。

**字段映射**（游戏里的变量 → 档案里的位置，接入时照着搬）：

| 游戏内 | 档案 | 生命周期 |
|---|---|---|
| `S.meta.weapon` / `S.meta.armor` | 不落盘 | **局内**，新局一律 `-1`（新手村） |
| `S.meta.skills{}` | 不落盘 | **局内**，新局一律 `{}` |
| `S.meta.arts{}` | 不落盘 | **局内**，新局一律 `{}` |
| `S.player.stones` | 不落盘 | **局内**，新局从 0 起 |
| `S.level` | `arcade.bestTier`（取 max） | 永久，只做展示 |
| `S.words`（`wordStat`） | `sm_words`（SRS 记录） | 永久 |

进局时 `js/arcade.js` 给一份空 meta（`freshMeta()`：`weapon/armor = -1`、`skills/arts = {}`），游戏侧 `S.meta` 拿到的就是新手村配置；退出时**一笔都不写回**。老档案里如果还留着 `arcade.equip / skills / arts`（旧版本写的），开局会用 `dropOldMeta()` 顺手清成 `null`，不参与任何计算。

## 6. 布局

### 6.1 四套

| 场景 | 视口 | 舞台（480×270 等比） | 输入区 |
|---|---|---|---|
| 手机竖 | 390×844 | 390×219，顶部留状态条 | **DOM 6×2 键盘**，贴底，键高 48 |
| 手机横 | 844×390 | 689×390 居中 | canvas 内原字母盘 |
| iPad 竖 | 768×1024 | 768×432 | 下 1/3 分三栏：词卡 / 键盘 / 技能 |
| iPad 横 | 1024×768 | 1024×576 | 右侧 256px 侧栏 |

### 6.2 竖屏为什么必须把键盘搬出来

480 逻辑宽压到 390 = 0.81 倍，canvas 里 26 个字母横排后每键约 15px，**手指点不准**。

做法：`game.js` 增加 `layout: 'portrait'` 开关——canvas 只画战场与 HUD（血条/气劲/技能）+ 一条拼写条，**字母盘不画**；字母交给 canvas 外面那块 DOM 键盘，按键仍然走同一个 `kidLetter(ch)` / `kidBack()` 入口。

实现（已落地）：

| 文件 | 作用 |
|---|---|
| `arcade/keypad.js` | 建 26 键 + 退格、`pointerdown` 即触发、`mount/unmount/height` |
| `arcade/keypad.css` | 键盘样式，主应用与独立调试页共用一份 |
| `arcade/host.js` | 按视口比例决定挂不挂键盘，把容器剩余高度报给游戏 |
| `arcade/src/game.js` | `ARCADE.setLayout('portrait')` → 不画字母盘，改画拼写条 |

键位排布：**7 列 × 4 行**（A–Z 顺排，最后一行 5 键居中）+ 1 个退格，键高 46px（iPad 竖屏 56px）。
26 键按 6×2 排不下，7 列是"每行不超过 7 个、键宽仍 ≥44px"的最小行数。

容器高度由宿主实测：`容器高 − 键盘高` 再交给 `fit()`，所以画布不会被键盘压住。

### 6.3 断点

**不另造一套断点**，直接用视口比例：`h > w × 1.05` 判竖屏（`pickLayout()`）。

- 竖屏（手机竖、iPad 竖）→ 键盘搬出画布
- 横屏（手机横、iPad 横）→ 画布里的字母盘原样用，屏幕够宽不需要 DOM 键盘
- 转屏后等 160ms 再重算一次（iOS 改视口尺寸比 `resize` 事件晚一拍）

高度一律用 `100dvh`（iOS 地址栏与 iPad 分屏会变高）。

### 6.4 字母盘分层：11 个起两行，21 个起三行

横屏的字母盘是**场上所有单词去重后的字母集合**（A→Z）。词一长、场上怪一多，二十几个字母挤成一排时每格只剩 12px 宽，iPad 上也点不准。

现在按字母数自动分行：

| 字母数 | 行数 | 举例 |
|---|---|---|
| ≤ 10 | 1 行 | 8 个 → 8 |
| 11–20 | 2 行 | 11 → 6 + 5，20 → 10 + 10 |
| ≥ 21 | 3 行 | 21 → 7 + 7 + 7，26 → 9 + 9 + 8 |

- **平均分行**：`per = ceil(n / rows)`，余数自然落在前面几行，两行相差不超过 1 个。
- **方块一样大**：宽度按最满的那行算（`(可用宽 - 间距) / per`，上限 36），所以 26 个字母也是 36×26，而不是原来的 12×22。
- **只往上长，底边不动**：盘面底边永远是 `PAL_Y + PAL_H = 238`，多出来的行往上加（两行 h=58、三行 h=88）。这样「切换 / 跳过 / 退格」三个按钮的位置一次都不用改，还正好和最下面那行对齐。
- 三行时盘面顶到 y=150，词卡最底是 146（怪 y=176 时卡在 94~146），差 4px 不会压住字。
- 同一套几何**绘制、点击命中、教程热区**三处共用（`paletteBox()` / `paletteTiles()`），改一处三处一起变。

实测（1180×820 的 iPad 横屏，缩放 2.36）：26 个字母从原来的 28×52 屏幕像素变成 **85×61**，20 个字母两行 10+10。

### 6.5 大屏字号：画布内的字会自己长大，外壳上的不会

画布里的字是用逻辑像素画的，整块画布被放大几倍，字就跟着放大（iPad 横屏 ×2.36、竖屏 ×1.64）。但**外壳上的 DOM 文本是按手机写的绝对字号**，到 10 寸屏上就不够看了：底部提示 13px、结算标题 19px、词单 12px、三个统计格 19/11px。

`css/arcade.css` 末尾加了一段 `@media (min-width: 700px) and (min-height: 700px)`（iPad 竖屏 820×1180、横屏 1180×820 都命中；手机横屏 844×390 不命中）：

| 位置 | 手机 | iPad |
|---|---|---|
| 顶部状态胶囊 | 14.5 / 16px | 17 / 20px |
| 画布下的提示行 | 13px | **18px** |
| 结算卡片宽 | 360px | **560px** |
| 结算标题 / 副标题 | 19 / 12.5px | 27 / 16px |
| 星星大数字 | 40px | 54px |
| 三个统计格 | 19 / 11px | 32 / 15px |
| 本局词单 | 12px | 16.5px |
| 「回首页」按钮 | 内容宽 | 整行 60px 高 / 20px |

- 结算的「回首页」原来是颗裸 `.btn-main`（没有 `.sheet-btns` 包着），只有文字那么大一颗；现在通用加了 `.sheet-card > .btn-main { width: 100%; height: 50px }`，手机上也不再是一小坨。

#### 释义排版（已落地，2026-11-07 修订）

原来卡面 72 宽、15px 一行，只放得下 4 个汉字，1547 条里有 158 条（10%）被「…」吃掉后半截 —— 「使人愉快的；精彩的」只剩「使人愉…」。

| 情况 | 处理 |
|---|---|
| 15/14/13/12/11px 任一能单行放下 | 单行，取最大可用字号 |
| 都放不下 | 折两行，字号 12/11/10，优先在 `；，、` 处断 |
| 断点落在一对括号中间 | 断点挪到括号外，避免「意思是（」这种 |
| 两行仍超宽 | 才逐字截断加「…」 |

## 错题复盘系统（2026-11-13）

跨「每日 10 题 / 50 题挑战 / 知识点专项 / 武道擂台 / 单词闯关」的统一闭环：

### 主应用（app.js + memory.js）

- **记错因**：`MEM.wrong(fp, q, mid, mine)` 多存一个「孩子当时写的答案」
  （`r.mine`）和累计错次（`r.wrongN`）、最近订正时间（`r.fixedAt`）。
  只存题干的话，复盘只能说「正确答案是 Y」，说不出「你写的是 X」。
- **结果页 → 复盘页（screen='review'）**：有错题就不再直接给成绩单。
  顶部一句人话总结（「主要在『第三人称单数』错 2 道」，全是一题一类时说
  「错得比较散」）；按知识点分组卡；逐题卡 = 题干 / 你写的（红删除线）/
  正确的（绿）/ 为什么（tip）/ 🔊 听一遍 / ✏️ 只做这道。
  主按钮是「一道道做对（N 道）」，错题不清零不回首页；全对时保留原成绩单。
- **错题重练（startRedo）**：只考错的题，不给星、不进连击；答对
  `MEM.right`（明晚再对一次即毕业），答错排到队尾，同一题最多 3 次，
  做完回复盘页报账。
- **首页错题本卡片**：`MEM.recentWrong(99)` 非空就显示
  「错题本 · N 道还没弄懂 · 最常错：xx」，点开同一复盘页（错题 + 错词两块）。

### 单词闯关（arcade.js）

- 结算页「拼错 / 跳过」的词带上中文释义，新增「把这 N 个词再拼一遍」按钮，
  打开错词重拼小练习（practiceWords）：给中文拼英文，错 1 次给首字母、
  错 2 次给前一半、错 3 次亮全词让她照抄 —— 拼对即 `srsUpdate`，
  真的推进复习排期。
- `wrongWords(n)` 给错题本取「拼错过的词」；`noteMiss(list)` 收擂台的错词。

### 验证（puppeteer + server.py :8791，档案 TEST）

- 每日 10 题故意全错 → 复盘页 10 条明细、分组正确 → 重练全对只剩词块题 1 道
  （测试脚本点词块的对错，非 app 缺陷）→ 回首页错题本卡片仍在（还有 1 道）。
- PK 答错 3 题 → 结算页 3 条明细 + localStorage 落盘 → 跳
  `index.html?who=TEST&book=1` 自动开错题本（1 道语法 + 2 个词，toast 提示）。
- 错词重拼 2 词全对 → `sm_words` 里 `reps+1、step=2`，真的进了复习排期。

### 补丁：错词的销账与入口（2026-11-13）

- `wrongWords(n)` 只列 `r.needFix === 1` 的词（刚拼错、还没拼回来）：拼错时置 1，`srsUpdate` 拼对置 0。
  老存档里 `lapses > 0` 的历史错词不列 —— 那是闯关自己的复习队列，不该堆进错题本。
- `noteMiss()` 存下擂台上显示过的中文（`r.m`），词表没加载完也能显示释义。
- `practiceWords(list, onClose)`：`list` 可传 `{w, cn}`；练完/退出回调让调用方重画，
  错题本页面据此把已拼对的词从列表里去掉。

- 兼容老存档：没有 `needFix` 字段的词，按「来源是擂台 + 最近 7 天」认作待订正
  （`needFixOf()`），所以之前擂台上错的词也能被捞回来。
